# Backend — Agent Context

> READ THIS alongside the root `AGENTS.md` before touching any backend file.

## What lives here

All business logic that runs in the **Electron main process**. The renderer never imports from this directory — it talks over HTTP only.

## Services

### `executor.ts`

Executes a single run of a Routine using the opencode SDK.

- **Model strings** must be `providerID/modelID` (e.g. `anthropic/claude-opus-4-5`). Empty string = let server pick default. See `parseModelString()`.
- Streams events through `opencodeEventRelay` → `runStreamStore` → `eventBus` → SSE clients.
- Builds a conversation context from prior runs in the same session (stdout JSONL replay).

### `scheduler.ts`

Singleton `schedulerService` that manages `node-cron` jobs for `cron`-type triggers.

- Started at server boot (`server.ts`). Call `schedulerService.start()` once.
- `registerTrigger()` / `unregisterTrigger()` are called by the triggers route on CRUD operations.
- **Pre-flight guards**: skips if the routine's workspace folder is inaccessible, or if `run_mode=foreground` and no SSE clients are connected.
- Lazily imports `executor` to avoid circular dependency — do not change this to a top-level import.

### `opencodeServerPool.ts`

Pool of opencode server contexts (one per workspace). Contexts are expensive to start.

- Always acquire with `acquireContext()` and **always `release()` in a `finally` block**.
- Call `invalidateAll()` after changing a Routine's model/config (routes do this).
- Call `disposeAll()` on app quit.

### `eventBus.ts`

In-process pub/sub for SSE. Each connected renderer client gets its own `AsyncQueue`.

- `eventBus.broadcast(event, data)` — sends to all connected clients.
- `eventBus.hasActiveClients` — used by scheduler to skip foreground-only runs when no one is watching.
- The SSE endpoint in `server.ts` calls `subscribe()` / `unsubscribe()`.

### `secureStorage.ts`

Wraps Electron's `safeStorage` API for OS-level encryption of secret settings.

- `encryptIfSecret(value, isSecret)` — call before writing to DB.
- `decryptIfSecret(value, isSecret)` — call after reading from DB.
- Gracefully falls back to plaintext if `safeStorage.isEncryptionAvailable()` returns false (e.g. headless CI).

### `permissionBridge.ts`

Decouples `opencodeEventRelay` from the Electron dialog API.

- Main process calls `setPermissionDialogHandler(fn)` at startup to wire in the Electron dialog.
- Relay calls `showPermissionDialog(req)` — returns `'once' | 'always' | 'reject'`.
- Defaults to `'reject'` if no handler is registered.

## Repositories

Thin wrappers over SQLite prepared statements. **No business logic.**

### Conventions

- **JSON columns** (`env_vars`, `config`, `permissions`, `metadata`): always `JSON.stringify()` on write, `JSON.parse()` on read. This happens at the repository boundary.
- **Booleans**: stored as `INTEGER` (`1` / `0`). Convert with `enabled ? 1 : 0` on write, `row.enabled === 1` on read.
- **IDs**: `randomUUID()` generated by the caller (route), passed into `repository.create()`.
- **Partial updates**: use the pattern in `routinesRepository.update()` — build `updates[]` and `values[]` arrays, only set provided fields.

### Test mocking pattern

`better-sqlite3` is a native module compiled for Electron's Node version — it won't load in Vitest's Node. Mock the entire `database` module:

```ts
vi.mock('../database', () => ({
  db: {
    prepare: vi.fn().mockReturnValue({ run: vi.fn(), get: vi.fn(), all: vi.fn() }),
  },
}));
```

See `routinesRepository.test.ts` for the full pattern.

## Routes

All routes follow the same pattern:

```ts
import { Hono } from 'hono';
import { zValidator } from '@hono/zod-validator';
import { SomeSchema } from '../types';

const router = new Hono();

router.post('/', zValidator('json', SomeSchema), (c) => {
  const data = c.req.valid('json'); // already validated + typed
  // ...
});
```

- Validate input with `zValidator('json', Schema)` — never trust `c.req.json()` directly.
- Return 404 with `{ detail: '...' }` for missing resources.
- Return 204 (no body) for DELETE.
- After mutating a Routine, call `eventBus.broadcast(...)`, `regenerateOpencodeConfig()`, and `invalidateAll()` — see `routes/routines.ts` for the canonical example.

## Side-effects after mutations

When a Routine changes, three things must happen (in this order):

1. `eventBus.broadcast('routine_updated', { routine })` — notifies SSE clients
2. `regenerateOpencodeConfig()` — rewrites the opencode config file
3. `await invalidateAll()` — clears the opencode server pool so it picks up the new config

Missing any of these causes stale state in the UI or the opencode runner.
